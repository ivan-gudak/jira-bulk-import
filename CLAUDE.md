# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Set up environment
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Run importer (from project root)
python src/main.py                      # uses .jira.ids, exports to .data/
python src/main.py path/to/custom.ids   # custom IDs file
python src/main.py --export-dir=output  # custom export directory
```

There are no tests or linting configured. The script must be run from the project root — `JiraAuth` and output paths resolve relative to `os.getcwd()`.

## Configuration

Credentials are read from `.jira.config` (key-value, `KEY: value` format) or env vars `JIRA_SERVER`, `JIRA_EMAIL`, `JIRA_TOKEN`. Env vars take precedence. Both files are gitignored and must never be committed.

`JIRA_BASE_URL` in `src/config.py` is hard-coded to `https://dt-rnd.atlassian.net`. Update it there if the Jira instance changes.

## Architecture

`main.py` orchestrates everything: reads `.jira.ids`, authenticates via `JiraAuth`, then calls `import_ticket()` per ID. Each ticket writes two files under `<export-dir>/<ID>/` (default `.data/`):

- `<ID>.md` — main ticket markdown (generated by `MarkdownGenerator`)
- `<ID>-comments-<date>.md` — comments file (generated by `CommentsHandler`)

**Module responsibilities:**

| Module | Role |
|---|---|
| `config.py` | `FIELD_MAPPING` (display name → Jira field ID), `EXPORT_FIELDS` (ordered list for frontmatter), `JIRA_BASE_URL` |
| `jira_auth.py` | Reads credentials, returns a `JIRA` client |
| `markdown_generator.py` | Builds the main `.md` file: YAML frontmatter + body sections; orchestrates attachment download |
| `attachment_handler.py` | Downloads attachments; deduplicates by SHA-256 into `attachments_shared/`; rewrites inline `!image.png` refs |
| `comments_handler.py` | Fetches comments via Jira API, formats each as markdown |
| `field_formatter.py` | Formats individual field types (users, arrays, parent links, linked issues) |
| `jira_markup_converter.py` | Converts Jira wiki markup → markdown |

**Attachment deduplication:** Files are stored as `<sha256_8>_<filename>` in `<export-dir>/<ID>/attachments_shared/`. Per-run `attachments/` dirs hold symlinks or copies pointing there. Re-running on the same ticket skips unchanged files.

**Adding a new Jira field:** Add the display name → field ID mapping to `FIELD_MAPPING` in `config.py`, then add the display name to `EXPORT_FIELDS` in the desired position. If the field needs special formatting, add a case in `MarkdownGenerator._extract_field_value()` and a helper in `FieldFormatter`.
